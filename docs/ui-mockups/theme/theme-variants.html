TollGate theme — three candidate palettes, same components

Built from the real admin dashboard and the real guest balance page (Playwright captures of :5199 and :5177), repainted from token values only. Each column is one palette; the components, spacing and copy are identical, so the difference you are judging is colour alone. The mono block under each is measured, not estimated: tools/contrast.py for the WCAG 2.1 ratio, tools/glare.py for the same pair after a 0.10 reflected-luminance veil (a typical laptop opposite a window).

Two defects the palette alone did not fix

Both were found by screenshotting the running app after the retheme and reading the pixels, not by looking at the token table. Each is a pair the token gate could not see: one is baked into a PNG, the other is produced by opacity at paint time.

1 · The wordmark was black on a near-black page

BRAND.logo resolved to logo-colour.png (ink #090909) on the dark palette. 1.10:1 — the wordmark was painted, and invisible.

TollGate
BEFORE · #090909 on #14161d · 1.10:1
TollGate
AFTER · #ffffff on #14161d · 18.07:1

Fix: admin/src/components/brand-logo.tsx picks the asset by prefers-color-scheme — the same <picture> swap the guest header already used. Now gated in tools/contrast.py as brand wordmark (image ink, not a token), because a token gate cannot see a PNG.

2 · The disabled button was the unreadable state

.btn:disabled { opacity: .45 } composites the fill and the label toward the page. Coral #ff6961 became rgb(130,64,66), the dark label became rgb(27,25,31): 2.29:1. The login page opens with Sign In disabled.

Sign In — before (opacity .45 · 2.29:1)
Sign In — after (token pair · 7.80:1)

Fix: explicit --disabled-bg / --disabled-text / --disabled-border tokens in both palettes instead of opacity. WCAG 1.4.3 exempts inactive controls, so this was never an AA failure — it is simply what the report described, in the state the page shows first. Now gated at AA.
